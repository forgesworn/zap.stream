# Login compatibility verification

The automated login suite covers every login route retained from upstream and both remote-signer
routes added in this fork. Run `bun run test:e2e` after installing Playwright Chromium. CI runs the
same tests on desktop Chromium and the Pixel 7 browser profile, with one worker and no retries.

| Route | Assertions |
| --- | --- |
| NIP-07 extension (Bark contract) | Public identity, genuine signature, reload, menu logout, absent/rejected provider, provider without NIP-44 |
| Private key | Both nsec and hex, genuine signature before/after reload, menu logout, invalid input |
| Create account | Generated key derives the saved identity, signed profile, local publication, reload, menu logout |
| NIP-46 bunker and QR | Actual encrypted loopback WebSocket requests, genuine signature, restore, menu logout and cross-tab invalidation |
| NIP-55 (Cambium contract) | Public identity only in storage, full-event signature verification, copied NIP-44 results including whitespace, restore without reapproval of public key, menu logout, cancelled approval/retry, wrong-account rejection/retry |

Every browser case also fails on uncaught page errors. This caught a real NIP-46 logout race:
subscription CLOSE messages were queued in promises while the socket was destroyed immediately.
Revocation still happens synchronously; socket destruction now runs on the next event-loop turn,
allowing those already queued messages to finish. The bunker/QR browser cases exercise this path
in both tabs. Tests use the actual screens for login and logout; publisher calls request signatures
without publishing chat. Account-creation profile publishing is intercepted locally.

The unit/integration tests separately cover exact event/identity binding, forged signatures,
NIP-04/NIP-44 peer and Unicode payload preservation, cancellation, timeouts, request ownership,
storage failure, malformed saved identities, logout, account replacement and stale session callbacks.

## Cambium source interoperability

On 2026-11-15, six URIs generated by this fork's `AndroidSigner` were fed through Cambium's actual
Kotlin `IncomingNip55RequestParser` and `WebNip55ResultBuilder`, compiled on the host JVM from commit
[`545eb68f517d4fe1179f3ecde898aefb099b27d8`](https://github.com/forgesworn/cambium/commit/545eb68f517d4fe1179f3ecde898aefb099b27d8).
The test used the committed `Nip55Request.kt`, `WebNip55Request.kt`, `RequestedPermissions.kt` and
`EventJson.kt`, with kotlinx.serialization 1.7.3. The Cambium working checkout was not modified.

All six passed: `get_public_key`, `sign_event`, `nip04_encrypt`, `nip04_decrypt`, `nip44_encrypt`,
`nip44_decrypt`. Assertions checked exact decoded payload (including `? + & 日本語`), selected identity,
recipient, parsed request type, app name, uncompressed full-event return, no callback URL, clipboard
result equality and the prohibition on remembered browser package permissions. Signature validation
and independent NIP-04/NIP-44 cryptographic round trips are covered by the frontend tests.

This JVM check is a recorded source interoperability check; CI's NIP-55 browser provider is a
protocol fixture. Neither is an Android app launch or a Heartwood hardware test. Desktop/Pixel
profiles exercise browser layout and interaction, not an Android operating system. Previously
recorded real Bark and Signet checks complement these fixtures; the suite does not install either app.

## Isolation

Playwright blocks HTTP requests to public hosts and intercepts public relay WebSockets. NIP-46
requests go to a loopback relay fixture with disposable signing and transport keys. No test publishes
chat or authentication events to a public relay, makes a payment, changes a signer permission or
contacts a maintainer. Test servers and relay fixtures are stopped by Playwright at completion.
