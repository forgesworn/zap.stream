# Login compatibility verification

The automated login suite covers every login route retained from upstream and both remote-signer
routes added in this fork. Run `bun run test:e2e` after installing Playwright Chromium. CI runs the
same tests on desktop Chromium and the Pixel 7 browser profile, with one worker and no retries.

| Route | Assertions |
| --- | --- |
| NIP-07 extension (Bark contract) | Public identity, genuine signature, reload, menu logout, absent/rejected provider, provider without NIP-44 |
| Private key | Both nsec and hex, genuine signature before/after reload, menu logout, invalid input |
| Create account | Generated key derives the saved identity, signed profile, local publication, reload, menu logout |
| NIP-46 bunker and QR | Actual encrypted loopback WebSocket requests, genuine signature, restore, menu logout and cross-tab invalidation |
| NIP-55 (Cambium contract) | Public identity only in storage, full-event signature verification, copied NIP-44 results including whitespace, restore without reapproval of public key, menu logout, cancelled approval/retry, wrong-account rejection/retry |

Every browser case also fails on uncaught page errors. This caught a real NIP-46 logout race:
subscription CLOSE messages were queued in promises while the socket was destroyed immediately.
Revocation still happens synchronously; socket destruction now runs on the next event-loop turn,
allowing those already queued messages to finish. The bunker/QR browser cases exercise this path
in both tabs. Tests use the actual screens for login and logout; publisher calls request signatures
without publishing chat. Account-creation profile publishing is intercepted locally.

The unit/integration tests separately cover exact event/identity binding, forged signatures,
NIP-04/NIP-44 peer and Unicode payload preservation, cancellation, timeouts, request ownership,
storage failure, malformed saved identities, logout, account replacement and stale session callbacks.

## Cambium source interoperability

On 2026-11-15, six URIs generated by this fork's `AndroidSigner` were fed through Cambium's actual
Kotlin `IncomingNip55RequestParser` and `WebNip55ResultBuilder`, compiled on the host JVM from commit
[`545eb68f517d4fe1179f3ecde898aefb099b27d8`](https://github.com/forgesworn/cambium/commit/545eb68f517d4fe1179f3ecde898aefb099b27d8).
The test used the committed `Nip55Request.kt`, `WebNip55Request.kt`, `RequestedPermissions.kt` and
`EventJson.kt`, with kotlinx.serialization 1.7.3. The Cambium working checkout was not modified.

All six passed: `get_public_key`, `sign_event`, `nip04_encrypt`, `nip04_decrypt`, `nip44_encrypt`,
`nip44_decrypt`. Assertions checked exact decoded payload (including `? + & 日本語`), selected identity,
recipient, parsed request type, app name, uncompressed full-event return, no callback URL, clipboard
result equality and the prohibition on remembered browser package permissions. Signature validation
and independent NIP-04/NIP-44 cryptographic round trips are covered by the frontend tests.

This JVM check is a recorded source interoperability check; CI's NIP-55 browser provider is a
protocol fixture. Neither is an Android app launch or a Heartwood hardware test. Desktop/Pixel
profiles exercise browser layout and interaction, not an Android operating system. Previously
recorded real Bark and Signet checks complement these fixtures; the suite does not install either app.

## Amber compatibility

Amber 6.6.9 is **not verified for the Android clipboard route**. Its
[`getIntentDataWithoutExtras` parser](https://github.com/greenart7c3/Amber/blob/v6.6.9/app/src/main/java/com/greenart7c3/nostrsigner/service/IntentUtils.kt#L194-L222)
decodes the entire URI before separating the payload from query parameters. A `%3F` inside an
encoded event or message becomes a `?` delimiter and truncates the payload. Reproducing that
source expression with this fork's encoded event containing `hello?` produces invalid event JSON.
This is a source-level reproduction, not an installed Amber APK test.

The login screens and README direct Amber users to **Remote signer** with a bunker link. That
route avoids the Android URI parser. The NIP-46 protocol is covered by the loopback suite;
an installed Amber app has not been exercised, so this recommendation is not a compatibility receipt.

## Cambium installed-device acceptance

**Status: passed for the recorded development build and device combination.** On 2026-11-16,
the physical Pixel 10 Pro XL on M4 completed the browser launch, Cambium 0.9.1 one-shot approval,
real clipboard return, independent signature verification, reload, NIP-04/NIP-44 in both directions,
decline/cancel/retry, late-result rejection and two-tab logout checks. See the
[physical receipt](pixel-cambium-2026-11-16.md) and its
[structured assertions](pixel-cambium-2026-11-16.json). Heartwood's firmware revision was not observed;
hosted production and other installed signers still require their own acceptance.

The procedure below is retained for repeat runs. The recorded run used the existing user-authorised
pairing without changing its identity, keys or grants.

Use an Android browser, the signed Cambium APK and a paired, reachable Heartwood with a disposable
identity. Preserve existing pairings, user keys and unrelated app grants. Record the exact frontend
commit, APK version and SHA-256, Android/browser versions, Heartwood firmware and each result.
An emulator can supplement this check but does not establish physical-device acceptance.

1. Serve the reviewed frontend with `bun run start --host 127.0.0.1 --port 5179 --strictPort`.
   With the chosen phone attached, run `adb -s <serial> reverse tcp:5179 tcp:5179` and open
   `http://127.0.0.1:5179` in its browser. Record that URL and the frontend commit. This is the
   development build; acceptance of a hosted production build requires its own build and URL.
2. Choose **Login → Android signer → Connect Android signer → Open Android signer**. The link
   must launch the installed Cambium app, not just have the expected URI in a browser fixture.
   Approve the selected disposable identity, return to the same browser tab and paste the copied
   public key. Expect the matching identity and only public identity data for the NIP-55 session.
3. In that tab's remotely attached Chrome DevTools console, request a controlled event:

   ```js
   const { Login, getPublisher } = await import('/src/login.ts')
   const signed = await getPublisher(Login.snapshot()).note('? + & 日本語', eb => eb.kind(1))
   console.log(JSON.stringify(signed))
   ```

   While the promise waits, use the browser prompt to open Cambium. Expect one-shot web approval
   without a remembered browser grant, plus any confirmation required by the Heartwood policy.
   Paste the copied full event into the browser prompt. Independently verify its signature, identity,
   kind, time, content and tags against the requested event. This publisher call constructs an event;
   do not call `broadcast`, publish chat or make a payment.
4. Reload and repeat signing. Expect the same identity, no repeated public-key request, and a fresh
   Cambium approval for signing. Exercise NIP-04 and NIP-44 round trips through the same installed-app
   prompt, including the special-character plaintext above, and verify with an independent peer.
5. Decline a Cambium signing request, cancel its pending browser prompt, then retry. Expect no
   signature from the declined operation, no identity change, and successful signing on the retry.
6. Start another signing request and log out before completing it. Expect its browser prompt to
   disappear, the pending operation to reject and a later copied result to leave the user logged out.
   Repeat logout with a second browser tab open; both tabs must discard the saved session.
7. Record passes, failures and unexercised checks in the receipt. Stop the task's dev server, remove
   only its ADB reverse mapping and delete task-owned captures after retaining the reviewed evidence.

## Isolation

Playwright blocks HTTP requests to public hosts and intercepts public relay WebSockets. NIP-46
requests go to a loopback relay fixture with disposable signing and transport keys. No test publishes
chat or authentication events to a public relay, makes a payment, changes a signer permission or
contacts a maintainer. Test servers and relay fixtures are stopped by Playwright at completion.
